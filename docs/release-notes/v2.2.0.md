# v2.2.0

Released: 2026-05-31T22:30:35Z

## v2.2.0

### Added
- **Wizard-style containerized installer** — Zero-dependency install path for new users. A user with only Docker installed can now run `curl -fsSL .../install.sh | bash && ./aithena/start.sh`. The installer bootstraps via a `python:3.12-slim` container when Python 3.12/uv are not available locally; runs natively if they are. Supports NVIDIA/Intel GPU detection, SSL, single-node vs distributed topology, and configurable library path. Complexity score drops from 6.5/10 to ≤3/10. (#1578)
- **Pre-flight checks** — Installer validates Docker daemon, disk space, internet connectivity, and docker group membership before prompting. Provides actionable error messages on failure. (#1578)
- **`.env.example`** — Comprehensive template with all required variables documented, aiding first-time configuration and air-gapped installs. (#1578)
- **Containerized installer image** — `ghcr.io/jmservera/aithena-installer:latest` published as part of the release pipeline. Version-locked to the app release. (#1578)

### Fixed
- **Prod overlay volume configs** — `docker/compose.prod.yml` `rabbitmq-data` and `redis-data` volumes no longer contain `driver_opts` bind-mount stubs that overrode the Docker-managed volume declarations in the base compose file. Resolves the Phase 1a volume migration gap introduced in PR #1612. (#1613)
- **Solr-init replication factor cap** — The inline heredoc entrypoint in `docker-compose.yml` now caps `SOLR_REPLICATION_FACTOR` to `SOLR_EXPECTED_NODES`, matching the safety logic already present in `docker/solr-init.sh`. Prevents collection health going RED when a stale `.env` carries `SOLR_REPLICATION_FACTOR=3` on a single-node deployment. (#1544)
- **E2E Playwright 429 rate-limit loop** — CI Playwright global-setup now reuses the `E2E_API_TOKEN` minted by the preceding `curl` step instead of issuing a second `/v1/auth/login`, eliminating the chronic 429 that required 1–3 reruns on every PR. (#1583)

### Security
- **Clear-text logging of sensitive data (CodeQL #233)** — `installer/setup.py:863` was logging sensitive values in plain text. Fixed by masking or omitting the value from log output. GHAS alert dismissed after fix confirmed. (#1576)
- **`COPILOT_ASSIGN_TOKEN` PAT refreshed** — Expired token replaced; Copilot auto-assignment restored to full permissions (no longer degraded to `GITHUB_TOKEN` fallback). (#1574)

### Milestone
- 6 issues closed: #1544, #1574, #1576, #1578, #1583, #1613
