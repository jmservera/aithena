## Summary

Aithena v2.2.0 is a **maintenance and installer improvement release** with no breaking changes:

1. **Containerized installer (#1578)** — Wizard-style zero-dependency install path. Users with only Docker installed can complete setup in 2 commands. Reduces installation complexity from 6.5/10 to ≤3/10.
2. **Prod overlay volume fix (#1613)** — Removes lingering bind-mount `driver_opts` from `docker/compose.prod.yml` that were overriding Docker-managed volume declarations, completing the Phase 1a volume migration.
3. **Solr-init replication factor cap (#1544)** — Aligns the inline heredoc entrypoint with `docker/solr-init.sh` safety logic to prevent collection health going RED on single-node deployments with stale config.
4. **E2E CI 429 fix (#1583)** — Eliminates a chronic Playwright global-setup rate-limit failure that required 1–3 reruns on every PR merge.
5. **Installer security fix (#1576)** — CodeQL alert #233: clear-text logging of sensitive data in `installer/setup.py:863` fixed and GHAS alert resolved.
6. **`COPILOT_ASSIGN_TOKEN` refresh (#1574)** — Expired PAT replaced; Copilot issue auto-assignment fully restored.

**Breaking Changes:** None.

### 2. Solr-Init Replication Factor Cap (#1544)

**Expected behavior:**
- Inline heredoc in `docker-compose.yml` contains the same `REPLICATION_FACTOR` cap logic as `docker/solr-init.sh`:
  ```bash
  if [ "${REPLICATION_FACTOR}" -gt "${EXPECTED_NODES}" ]; then
    REPLICATION_FACTOR="${EXPECTED_NODES}"
  fi
  ```
- OR the inline heredoc has been replaced with a call to `docker/solr-init.sh` (preferred approach per issue)
- On a clean single-node deployment with `SOLR_REPLICATION_FACTOR=3`, collection health should be GREEN with 1 active replica

**Where to verify:**
- `docker-compose.yml` around line 820 — `solr-init` service entrypoint heredoc
- `docker/solr-init.sh` line 112–115 — reference implementation

**Issue evidence:**
- Bug confirmed during local E2E testing. Root cause (missing cap) was well-defined.
- Fix was straightforward: either add the safety condition or delegate to the standalone script.

**Risk if unfixed:**
**HIGH (for single-node)** — Stale `.env` files (very common after in-place upgrades) would produce 0 active replicas with no obvious error until `add-conf-overlay.sh` fails.

## Recommended Validation Before Production Use

1. **Volume config validation (5 min):**
   ```bash
   docker compose -f docker-compose.yml -f docker/compose.prod.yml config | grep -A5 -B2 "rabbitmq-data\|redis-data"
   ```
   Confirm no `driver_opts` blocks appear for those volumes.

2. **Single-node Solr health check (10 min):**
   ```bash
   # With SOLR_REPLICATION_FACTOR=3 in .env, bring up single-node overlay
   docker compose -f docker-compose.yml -f docker/compose.single-node.yml up -d
   # Wait for solr-init to complete, then:
   curl -u admin:$SOLR_ADMIN_PASSWORD "http://localhost:8983/solr/admin/collections?action=CLUSTERSTATUS" | jq '.cluster.collections.books.shards[].replicas[].state'
   # Expected: all "active"
   ```

3. **CI E2E smoke test (verify fix in place):**
   ```bash
   grep -n "E2E_API_TOKEN\|auth/login" e2e/playwright/global-setup.ts | head -20
   ```
   Confirm `E2E_API_TOKEN` is checked before issuing a login request.

4. **Fresh installer test (15–30 min, recommended):**
   ```bash
   # On a clean Ubuntu VM with Docker only:
   curl -fsSL https://raw.githubusercontent.com/jmservera/aithena/main/install.sh | bash
   ./aithena/start.sh
   curl -sf http://localhost/ && echo "✅ UI accessible"
   ```

5. **Security alert confirmation:**
   - Navigate to GitHub Security → Code scanning → Alert #233
   - Confirm status is "Dismissed" (with justification) or "Fixed"
