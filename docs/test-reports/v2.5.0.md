## Summary

v2.5.0 is a major infrastructure release delivering the Solr 9→10 migration. The evidence path covers:

1. HNSW schema compatibility: parameter names renamed and tested across Solr 9 (shim) and Solr 10 (native).
2. solr-init CLI rewrite: all `bin/solr` invocations updated to Solr 10 double-dash syntax and validated.
3. `blockUnknown=true` posture: health checks, CI probes, and admin tooling authenticate correctly against secured Solr 10 endpoints.
4. `wt=json` enforcement: all `solr-search` HTTP query paths lock JSON responses; integration tests verify the response schema.
5. PathHierarchyTokenizer: confirmed no-op — folder-path facet tokenization unchanged in Solr 10.
6. Security UI scaffold: Admin → Security page added; backend access controls hardened and audited.
7. Solr 10 default runtime cutover: `solr:10` is the default base image. Tika service added. Solr 9 rollback overlay preserved.
8. E2E and preflight test coverage: Playwright tests validate the full Solr 10 startup, auth, and collection health path.
9. OpenVINO release gate hardening: OpenVINO version constraints locked to base image; smoke test diagnostics capture package versions on failure.

PR #1670 (int8 quantization bits fix) remains on owner hold and is **excluded from v2.5.0**. `VECTOR_QUANTIZATION=int8` is not a supported configuration for this release.

## Critical Validations

- **HNSW parameter migration**: PR #1667 renames `hnswMaxConnections`→`hnswM` and `hnswBeamWidth`→`hnswEfConstruction`. Both field names are covered by integration tests against Solr 10. The Solr 9 compatibility shim in `solr-init` rewrites to legacy names for Solr 9 rollback deployments.
- **`blockUnknown=true` posture**: PR #1663 verifies that Solr 10's secure-by-default posture is handled correctly. Health checks, `solr-init` probes, and CI validation scripts now pass credentials. No unauthenticated probes reach Solr 10 in the default configuration.
- **`wt=json` enforcement**: PR #1664 locks all Solr responses to JSON format. Integration tests assert that search, status, and stats endpoints continue to parse correctly under Solr 10.
- **PathHierarchyTokenizer**: PR #1665 confirms the `folder_path_s` field type is unchanged in Solr 10. No schema migration needed for folder-path facets.
- **Tika service**: PR #1680 adds `tika` as a dedicated container in the Compose stack. CI confirms the service starts and the document indexer communicates with it correctly.
- **Solr 9 rollback overlay**: PR #1680 preserves `docker/compose.solr9.yml`. The overlay is validated in CI to confirm it correctly pins Solr 9 and rewrites HNSW parameter names.
- **OpenVINO smoke gates**: PR #1666 adds a runtime matrix regression test inside the built Docker image. The smoke test now captures full `pip list` output, OpenVINO version string, and startup logs on failure. OpenVINO 2025.4 constraint prevents lockfile version skew with the base image.
- **Scalar quantization hold**: PR #1670 remains on owner hold. The `int8` code path is present in code (merged via #1669) but is **not activated** in the v2.5.0 configset or documentation. Operators setting `VECTOR_QUANTIZATION=int8` will encounter unsupported behavior until v2.5.1.

## Known Gaps / Accepted Risks

- **No full production reindex validation in CI**: The CI integration tests use a small fixture collection. A full production reindex against a 9M-page library was not run as part of release validation. Operators should follow the production runbook and validate search quality after reindex on their actual collection.
- **Performance benchmarks not completed**: Solr 10 vector search performance benchmarks (efSearchScaleFactor tuning, query latency comparison vs Solr 9) are deferred to v2.5.1. No performance regressions were observed in CI fixture runs, but quantitative baseline comparisons are pending.
- **`int8` scalar quantization excluded**: PR #1670 resolves a Solr 10 quantization bits incompatibility but remains on owner hold. `VECTOR_QUANTIZATION=int8` is not supported in v2.5.0. Deployments relying on int8 for memory savings must remain on `none` or `fp16` until v2.5.1.
- **Solr 9 rollback overlay is temporary**: The `docker/compose.solr9.yml` overlay is supported for a transitional period only. It will be removed in a future release. Operators should plan to complete the Solr 10 migration promptly.
- **cuVS GPU codec deferred**: GPU-accelerated indexing via Solr's cuVS codec is not included in v2.5.0. Deferred to v2.5.1+ with a separate NVIDIA-enabled Solr image variant.
