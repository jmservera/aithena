## Summary

Aithena v2.2.1 is a **maintenance patch release** that supersedes the published v2.2.0 tag and focuses on safer upgrades plus better release/test reliability:

1. **Prod overlay volume migration follow-up (#1616)** — `docker/compose.prod.yml` no longer carries the lingering bind-mount override pattern for `rabbitmq-data` and `redis-data`, reducing upgrade risk on production hosts.
2. **Solr-init replication factor safety cap (#1544)** — Single-node deployments with stale `SOLR_REPLICATION_FACTOR` values no longer create RED collection health at startup.
3. **E2E login rate-limit fix (#1583)** — Playwright global setup now reuses `E2E_API_TOKEN` when present, avoiding redundant `/v1/auth/login` calls in CI.
4. **Real-library fixture skip (#1617)** — Document-indexer tests now skip cleanly when maintainer-only fixtures are absent, improving local and CI stability.
5. **E2E skeleton coverage scaffolding (#1623)** — Release notes document new deterministic coverage scaffolding for thumbnails, downloads, and recovery scenarios.

**Breaking Changes:** None at the application/runtime level. Operators preserving older bind-mounted prod-overlay state should still back up and migrate that data deliberately before restart.

### 2. Solr-Init Replication Factor Cap (#1544)

**Expected behavior:**
- The inline `solr-init` entrypoint in `docker-compose.yml` caps `REPLICATION_FACTOR` to `EXPECTED_NODES`
- `docker/solr-init.sh` retains the same safety guard so both code paths agree
- Single-node deployments tolerate stale `SOLR_REPLICATION_FACTOR=3` style settings without producing RED collection health

**Where to verify:**
- `docker-compose.yml` — `solr-init` entrypoint around lines 807–823
- `docker/solr-init.sh` — validation logic around lines 107–114

**Issue evidence:**
- `docker-compose.yml` contains the guard:
  ```bash
  if [ "$$REPLICATION_FACTOR" -gt "$$EXPECTED_NODES" ]; then
    REPLICATION_FACTOR="$$EXPECTED_NODES"
  fi
  ```
- `docker/solr-init.sh` contains the same guard for the standalone path
- Release notes call out #1544 as a core v2.2.1 reliability fix

**Risk if unfixed:**
**HIGH (single-node deployments)** — A stale `.env` could leave the `books` collection unhealthy on startup and block indexing/search until manually corrected.
